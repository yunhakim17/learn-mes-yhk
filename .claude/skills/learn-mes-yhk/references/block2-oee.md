## EXPLAIN

### 1. 정의

| 용어 | 뜻 |
|---|---|
| **OEE** (설비종합효율) | 설비가 돌 수 있었던 시간 동안 얼마나 제 속도로, 얼마나 양품을 만들었는지를 하나의 %로 나타낸 지표. 가용률 × 성능 × 품질 |
| **가용률** | 계획된 시간 중 설비가 실제로 돈 시간의 비율 (고장·셋업으로 깎임) |
| **성능** | 돈 시간 동안 기준 속도 대비 실제 속도의 비율 (짧은 정지·감속으로 깎임) |
| **품질** | 만든 것 중 양품의 비율 (불량·재작업으로 깎임) |
| **SPC** | 공정 측정값을 관리도에 찍어 불량이 나기 전에 공정이 흔들리는 것을 잡는 방법 |
| **LOT 추적** | 어떤 자재·설비·작업자를 거쳐 만들어졌는지 묶음 단위로 거슬러 올라가는 기능 |
| **OPC UA** | 서로 다른 회사의 설비와 소프트웨어가 같은 말로 데이터를 주고받게 하는 국제 표준 (IEC 62541) [S9] |

월드클래스 OEE는 85%이고, 구성 목표는 가용률 90% 이상 · 성능 95% 이상 · 품질 99.9% 이상이다 [S7][S8]. 일부 자료는 품질 목표를 99%로 적는데, 그러면 곱한 값이 85%에 조금 못 미친다. 99.9%로 해야 85%가 맞는다 [S7].

### 2. 왜 '연결'인가

| 연결 | 무엇을 잇나 | 끊겨 있으면 생기는 일 |
|---|---|---|
| 설비 → MES | PLC 가동/정지 신호를 MES 실적에 자동 기록 | 비가동 사유를 작업자가 나중에 기억으로 적음 → 가용률이 부정확 |
| 품질 → LOT | 검사 결과를 LOT 번호에 붙임 | 같은 자재를 쓴 다른 제품을 못 찾음 → 불량 확산 |
| 실적 → 납기 | MES 실적을 ERP 납기와 비교 | 지연을 출하 당일에야 앎 |
| SPC → 경보 | 측정값이 관리 한계를 넘기 전 추세를 감지 | 불량이 쌓인 뒤에야 공정을 멈춤 |

설비 데이터(가용률), 품질 데이터(불량), 납기 데이터(실적)는 이미 있다. 문제는 다른 화면, 다른 사람, 다른 시간에 있다는 것이다. OEE는 이 셋을 하나의 숫자로 묶는 가장 단순한 연결 고리다.

### 3. 케이스 — OEE 85%를 거꾸로 읽기

1. 가용률 90% × 성능 95% × 품질 99.9% → OEE 약 85% [S7]
2. 품질만 99%로 떨어지면, 나머지가 그대로여도 OEE는 85%에 못 미친다 [S7].
3. OEE는 가장 약한 고리 하나가 전체를 끌어내리는 구조다. 그래서 세 값이 모두 자동으로, 같은 시간 단위로 모여야 계산이 의미가 있다.

부품사가 MES 도입 후 불량률·리드타임을 얼마나 줄였는지 정량 수치를 공개한 사례는 찾지 못했다(미확보). 강의에서는 자기 회사 수치를 넣어 보는 것으로 대신한다.

## EXECUTE

아래 프롬프트를 붙여 넣으라고 안내한다.

```
mes-lab 폴더에서 2장 실습을 해 줘.
1. facts.csv 에서 F08(월드클래스 OEE)과 F09(가용률/성능/품질 목표) 행을 읽어 줘.
2. 가용률 × 성능 × 품질 로 OEE(%)를 계산해 줘. 소수 첫째 자리까지.
3. 품질만 99%로 바꿨을 때 OEE 도 계산해 줘.
4. out/ch2_oee.json 에 {"oee_world_class": 첫 번째 값, "oee_quality99": 두 번째 값} 으로 저장해 줘.
5. 가용률·성능·품질·OEE 네 막대와 85% 기준선을 그린 차트를 out/ch2_oee.png 로 저장해 줘.
   한글 글꼴이 깨지지 않게 하고, 차트 아래에 출처 [S7][S8]을 적어 줘.
6. facts.csv 는 고치지 마. facts.csv 에 없는 목표값을 쓰지 마.
7. 끝나면 두 OEE 값과 차트를 보여 줘.
```

### 확인할 것 (Phase B)

- `out/ch2_oee.json`이 `oee_world_class` = 85.4, `oee_quality99` = 84.6이다.
- `out/ch2_oee.png`가 있고, 막대 네 개와 85% 기준선이 보이며 한글이 깨지지 않았다(이미지를 직접 열어 확인).

막히면 "ch2_oee.json 의 두 값을 F09 의 세 숫자로 다시 곱해 검산하고, 다르면 원인을 찾아 줘"라는 후속 프롬프트를 준다. 정답은 "정답 보기" 요청이 있을 때만 연다.
