## EXPLAIN

### 1. 정의

| 용어 | 뜻 |
|---|---|
| **후행 지표** | 문제가 생긴 뒤에 확인되는 숫자 — 불량률, 납기 지연 |
| **선행 지표** | 문제가 생기기 전에 움직이는 숫자 — 진동 증가, 사이클 타임 증가, 실적 진도 |
| **조기경보 규칙** | "이 값이 이렇게 움직이면 사람이 알아채기 전에 알린다"를 미리 정해 둔 조건 |
| **GitHub Pages** | GitHub 저장소의 HTML 파일을 공개 웹 주소로 보여 주는 기능 |

| 막고 싶은 문제(후행) | 먼저 움직이는 신호(선행) | 신호가 나오는 층 | 조기경보 규칙 예 |
|---|---|---|---|
| 설비 정지 | 진동·온도 상승, 짧은 정지 증가 | Level 1~2 | 진동이 평소 범위를 벗어난 상태가 계속되면 알림 |
| 불량 발생 | SPC 관리도의 한쪽 쏠림·추세 | Level 3 (검사) | 측정값이 한 방향으로 계속 움직이면 공정 점검 |
| 납기 지연 | 실적이 계획 대비 뒤처지는 속도 | Level 3 ↔ 4 | 시간대별 실적 누적이 계획선 아래로 벌어지면 알림 |

### 2. 도입하면 무엇이 달라지나 — 두 조사를 읽는 법

| 출처 | 대상 | 품질 | 생산성 | 원가 | 납기 |
|---|---|---|---|---|---|
| 경남테크노파크 분석 (2026 보도) [S13] | 2022~2023년 도입 경남 기업 439곳 | +44.3% | +22.8% | -32.5% | +17.0% |
| 정부 전국 성과 (2022 보도) [S15] | 2014~2018년 참여 기업 | +42.5% | +28.5% | -15.5% | — |

두 조사는 대상·시기·측정 방법이 다르므로 숫자를 직접 비교하지 말고 방향만 읽는다. 둘 다 품질 개선 폭이 가장 크다는 공통점이 있다 [S13][S15]. 정부는 2025년 10월 'AI 기반 스마트제조혁신 3.0'에서 AI 스마트공장 1만 2천 곳 구축과 중소 제조업 AI 도입률 1% → 10%를 내걸었다 [S12].

### 3. 케이스 — 태정기공 (2024 스마트공장 우수사례) [S14]

부품 제조 공정에 AI 기반 생산관리 체계를 도입하고, 검사설비에 품질예측 AI 모델을 적용했다. 생산량 36.3% 증가, 불량률 약 91% 감소로 보고되었다 [S14]. 검사 결과를 '합격/불합격 기록'이 아니라 다음 불량을 예측하는 선행 신호로 바꾼 것이 핵심이다. 이 수치는 정부 보도자료 한 곳에만 있는 단일 출처라서 인용할 때 "우수사례로 보고된 수치"라고 밝힌다.

## EXECUTE

```
mes-lab 폴더에서 3장 실습을 해 줘.
1. facts.csv 의 F18(경남 성과)과 F20(전국 성과)을 읽어, 조사마다 개선 폭이 가장 큰 지표와
   그 값을 찾아 줘. 원가는 감소가 개선이니 절댓값으로 비교해 줘.
2. out/ch3_compare.json 에
   {"gyeongnam_top": 지표명, "gyeongnam_top_value": 값, "national_top": 지표명, "national_top_value": 값}
   으로 저장해 줘.
3. mes-lab/index.html 에 결과 대시보드 한 장을 만들어 줘.
   - out/ch1_map.json, out/ch2_oee.json, out/ch3_compare.json 의 값과 out/ch2_oee.png 를 보여 줘.
   - 두 조사는 대상·시기가 달라 방향만 읽는다는 문장을 넣어 줘.
   - docs/ 의 교재·덱 PDF 링크와 출처 번호를 넣어 줘.
   - 휴대폰 폭에서도 가로 스크롤이 없게 해 줘.
4. facts.csv 에 없는 숫자는 쓰지 마.
5. 공개 준비: mes-lab 을 git 저장소로 만들고, .gitignore 에 *.pptx, *.docx, 캡처 이미지(*.jpg, preview/)를 넣어 줘.
   올라갈 파일 목록을 보여 주고, 내가 "공개"라고 답하기 전에는 GitHub 에 올리지 마.
```

사람이 직접 하는 일:
1. GitHub에 로그인되어 있지 않으면, Claude가 안내하는 브라우저 로그인 화면에서 직접 로그인한다(비밀번호를 채팅에 쓰지 않는다).
2. 올라갈 파일 목록을 보고, 회사 내부 자료가 없으면 "공개"라고 답한다.
3. Claude가 알려 준 `https://<내 아이디>.github.io/mes-lab/` 주소를 휴대폰으로 열어 본다(1~2분 걸릴 수 있다).

### 확인할 것 (Phase B)

- `index.html`에 OEE 85.4%와 ISA-95 5층이 보이고, PDF 링크 두 개가 열린다.

막히면 "index.html 을 브라우저 폭 375px 로 열어 가로 스크롤과 깨진 링크를 찾아 고쳐 줘"라는 후속 프롬프트를 준다. 정답은 "정답 보기" 요청이 있을 때만 연다.

```json
AskUserQuestion({

      {"label": "방향만 쓴다", "description": "대상·시기가 달라 직접 비교할 수 없다. '두 조사 모두 품질 개선 폭이 가장 컸다'로 고친다"},
      {"label": "효과 없음으로", "description": "차이가 1.8%p뿐이라 의미가 없으니 '스마트공장은 효과 차이가 없다'로 고친다"},
      {"label": "최신 것만 남긴다", "description": "경남 자료가 더 최신이니 전국 수치는 지우고 경남 수치만 남긴다"}

정답: 1번. ① 두 조사는 대상(지역·기업 수), 시기, 측정 방법이 달라 숫자 크기를 직접 비교할 수 없다. 공통으로 읽을 수 있는 것은 "둘 다 품질 개선 폭이 가장 컸다"는 방향이다. ② '효과 없음'은 두 조사 모두 개선을 보고한 사실과 반대되는 결론이다. 최신 자료만 남기면 근거 하나를 지울 뿐, 비교 자체의 문제는 그대로다. ③ 현장 보고서에서도 출처가 다른 두 숫자를 나란히 둘 때는 "누가, 언제, 누구를" 쟀는지 함께 적고 방향만 말한다.

## 과제와 다음

1. **우리 공장 조기경보 규칙 한 문장** — 지난달 가장 아팠던 문제 하나를 고르고, 그보다 먼저 움직였을 신호와 그 신호가 나오는 층(Level)을 적은 뒤, 현장 작업자가 이해할 수 있는 경보 규칙 한 문장을 쓴다. 제출물: `mes-lab/out/my_rule.md`
2. **우리 라인 OEE 가장 약한 고리** — 자기 라인의 가용률·성능·품질로 OEE를 계산하고, 월드클래스 목표 대비 가장 벌어진 값을 찾는다. 회사 내부 숫자이므로 공개 저장소에 올리지 않는다. 제출물: 비공개 메모 한 장
3. **강의 하나 더 만들기** — 다른 Day나 내 업무 주제로 `/course-forge`를 다시 돌려 내 강의를 하나 더 만든다. 제출물: 새 `learn-` 저장소 주소
